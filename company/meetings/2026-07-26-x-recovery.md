## 2. X告知401の診断(桐生・鵜飼)

`auth_test.py`(投稿しない・鍵を表示しない検証スクリプト)で実測:

```
[OK] .env の形式は正常。X API に接続します…
[NG] 認証エラー(401)
```

- **原因確定: トークン失効**。ローカル`.env`の最終更新は**2026-06-11 17:08**、トークン再発行は6/12。
  つまり`.env`の中身は**再発行前の古い鍵**。形式・コピペの問題ではない
- 生きている鍵は kane-kizuki-bot の**GitHub Secrets側のみ**(書き込み専用のため読み出し不可)

### 鵜飼の注意喚起(重要)

同じXアプリの鍵を2か所で使っている:

```
X開発者ポータル(1アプリ)
  ├─ kane-kizuki-bot  → GitHub Secrets ← 現在稼働中(おっちゃん垢の自動投稿)
  └─ AI TECH TIMES    → ローカル.env   ← 401
```

**再発行すると古い鍵は即無効化され、稼働中のkane-kizuki-botが止まる。**
片方だけ直すと「動いているものを壊すだけ」になるため、**両方を同一作業で更新することが必須条件**。

## 3. 復旧手順(八重樫・設計)

社長の作業を3ステップ・1回で終わる形にする(社訓: 検証済み・1回で終わる形):

1. developer.x.com → 該当アプリ → Keys and tokens → **Access Token & Secret再生成**、4値をコピー
   - **App permissionsが「Read and write」であることを確認**(Readのみだと投稿時403)
2. 凪が開くメモ帳(`.env`)に4値を貼って保存
3. 凪が用意するbatをダブルクリック → GitHub Secretsに4値を登録
   - **Windowsの鉄則: パイプ禁止・必ず`--body`**(CR混入で401になる既知の罠)

事後検証: 凪が`auth_test.py`で接続確認 → 緑になってから完了報告(投稿はしない)。
